# RAGOps repository rules

## Working agreement

- Work autonomously inside this repository. Do not modify files outside the workspace.
- Do not edit `k8s/`; Member 2 owns Kubernetes manifests.
- Member 2 also owns live-query and coverage scripts, the metrics summary script, and the trace inspection tool. This repository provides the trace writer and API metrics endpoint.
- Do not invent test outputs, measurements, approvals, screenshots, or deployment evidence. Every reported number must be generated by this repository's real pipeline and committed under `eval/results/` or `traces/`.
- Keep `.env`, access tokens, and API keys out of Git. `.env.example` contains names and safe defaults only.
- Add no TODOs, placeholders, or manual work instructions. Commands that depend on Member 2's Kubernetes work must say `Member 2 fills this`.
- For items requiring human authorship/review, keep proposals in `eval/review/`. Do not set final review labels until the user replies `approved`.
- After each implementation step, run the relevant commands, show their output, update `PROGRESS.md`, then synchronize, commit, and push using the configured Git identity.

## Assignment facts

- The system needs document ingestion, a persistent vector store, retrieval, and an LLM generator.
- The demo must run on Kubernetes. A Docker-only demo receives zero.
- Run real evaluations and commit result files under `eval/results/`; commit trace samples under `traces/`.
- Batch A has at least 10 source documents. Batch B has at least 10 documents and includes exact and near duplicates, corrupt/truncated content, missing metadata, a newer version, and an injected instruction.
- Offline evaluation covers embeddings, retrieval, end-to-end answer quality, noise, and two seeded suite runs. Human questions/reviews are provisional until approved.
- Report sections map Parts A-F; the assignment also has Part G (report).

## Configuration contract

Read settings from environment variables with local defaults in `rag/config.py`:

`DATA_DIR`, `QUARANTINE_DIR`, `ARCHIVE_DIR`, `TRACE_DIR`, `VECTOR_DIR`, `COLLECTION`, `EMBED_MODEL`, `LLM_API_KEY`, `LLM_MODEL`, `TOP_K`, `SIMILARITY_THRESHOLD`, `CHUNK_SIZE`, `CHUNK_OVERLAP`, and `SEED`.

Required commands:

```powershell
python -m rag.ingest --data $env:DATA_DIR --collection $env:COLLECTION
python -m eval.run_suite
python -m eval.gate --candidate X.json --baseline Y.json --config gate.yaml
uvicorn rag.api:app --port 8000
```

The API routes are `/query`, `/health`, and `/metrics`. Chroma uses `VECTOR_DIR` for persistence. The ingestion module is the only vector-store writer; API handlers only retrieve. Embeddings use the local Sentence Transformers model `sentence-transformers/all-MiniLM-L6-v2`.

## Trace contract

Write one JSONL record per query with these fields: `trace_id`, `timestamp`, `user_query`, `rewritten_query`, `embedding_model`, `embedding_version`, `collection`, `retrieved[{chunk_id, doc_id, doc_version, score}]`, `filters`, `reranked_order`, `prompt_hash`, `prompt`, `model`, `params`, `response`, `citations`, `guardrail_actions`, `latency_ms{embed,retrieve,rerank,generate,total}`, and `cache_hit`.

`traces/example.jsonl` must come from a real query run.
